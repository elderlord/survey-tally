# 10x10 삼목 계획서

## 목표

10×10 판에서 두 사람이 번갈아 돌을 두어, 가로·세로·대각선으로 자기 돌 3개를 먼저 잇는 쪽이 이기는 게임.
`index.html` 하나로 브라우저에서 바로 동작한다.

## 규칙

| 항목 | 규칙 |
|---|---|
| 판 | 10×10 칸 |
| 차례 | 흑이 먼저, 이후 흑·백 번갈아 한 수씩 |
| 착수 | 빈 칸에만 둘 수 있다 |
| 승리 | 방금 둔 돌을 포함해 가로·세로·두 대각선 중 한 방향으로 같은 색 돌이 3개 이상 이어지면 승리 |
| 무승부 | 승자 없이 100칸이 모두 차면 무승부 |
| 종료 후 | 더 둘 수 없다. 새 게임 또는 무르기만 가능 |
| 무르기 | 마지막 한 수를 취소한다(게임이 끝난 뒤에도 가능) |

## 제약

- 파일은 `index.html` 하나. 외부 라이브러리·외부 글꼴·분석 도구를 쓰지 않는다.
- `Content-Security-Policy`를 `default-src 'none'`으로 두어 외부 연결을 막는다.
- 저장소 맨 위의 빈 `.nojekyll`은 GitHub Pages 배포용으로 유지한다.

## 구조

- `index.html`
  - `<script id="game-core">`: 게임 로직만. DOM을 건드리지 않고 `globalThis.Samok`에
    `SIZE`, `WIN_LENGTH`, `createGame`, `play`, `undo`, `findWinLine`을 내놓는다.
    상태는 바꾸지 않고 새 상태를 돌려준다(불변).
  - 그 아래 별도 `<script>`: 판 그리기, 클릭·키보드 입력, 상태 안내.
- `test/game.test.mjs`: `index.html`에서 `game-core` 블록만 꺼내 `node:vm`의 빈 환경에서 시험한다.
- `test/static.test.mjs`: 외부 자원·네트워크·저장 API가 없는지, CSP가 있는지 정적으로 검사한다.
- `package.json`: 의존성 없이 `npm test` → `node --test`.
- `.github/workflows/test.yml`: 푸시·PR마다 시험 실행.

## 화면

- 바둑판처럼 칸 가운데를 지나는 선 위에 돌을 놓는 모양.
- 현재 차례·승패·무승부 안내, 새 게임·무르기 버튼.
- 마지막 수 표시, 이긴 줄 강조.
- 키보드: 방향키로 칸 이동, Enter·Space로 착수. 각 칸에 "3행 4열, 흑" 같은 읽기용 이름.
- 라이트·다크 모드, 좁은 화면(375px)에서도 판이 화면 안에 들어온다.
